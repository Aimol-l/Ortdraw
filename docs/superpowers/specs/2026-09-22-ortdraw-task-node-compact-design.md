# Ortdraw 任务节点紧凑布局（后处理 / 预处理）— 设计文档

- 日期：2026-09-22
- 状态：待评审
- 范围：重新设计「后处理」节点（以及共用同一控件的「预处理」节点）的参数区与结果面板，使其更紧凑；把任务选择器与布尔参数合并到同一行，参数改为两列；分类任务的 Top-K 面板改为细行列表。
- 非目标：不改任务/参数的**语义与执行逻辑**（`TaskSpec`、预/后处理注册表、执行器不动）；不改节点卡片外壳（标题栏、端口、缩略图、选择态）；不改「ONNX 推理」节点；不引入新的设置项。
- 视觉稿：`.superpowers/brainstorm/16333-1790079556/content/postprocess-a2b-topk.html`（A2 + T1 为定稿）。

## 1. 目标

1. 后处理（检测/分割/分类）节点在默认宽度 288px 下的**纵向占用明显减少**：`yolo_detect` 参数区由 5 行 → 3 行（含任务行）。
2. 一行内放更多信息但**不牺牲可读性**：标签仍在（放进控件内部，灰字），值右对齐；控件高度统一收窄到 20px。
3. 分类任务的 Top-K 面板从「标题 + 5 条粗条」改为**细行列表**，去掉冗余标题。
4. 预处理节点与后处理节点**外观保持一致**（共用控件），避免两个节点风格分裂。
5. 宽高自适应行为不变：节点高度仍 = `max(getMinHeight(), contentHeight)`，`min_width` 不变。

## 2. 现状与约束

- `TaskNodeControls.qml` 负责「任务下拉 + 按 `paramDescs()` 自动生成参数行」，被 `PostProcessNode.qml` 与 `PreProcessNode.qml` 共用；单参数控件在 `ParamField.qml`。
- 现状：任务下拉占满整行；每个参数独占一行（标签列 46px + 控件，行高 22、行距 6）；参数按 `ParamDesc.group` 分组，`group>0` 的若干参数排在同一行（现行实现）；`ParamDesc.showIf*` 控制条件显隐（预处理已在使用）。
- `ParamDesc.kind` 取值：`bool`、`select`、`floats`（按 `vecCount` 拆多格，逗号存储）、`size2`（`WxH` 存储）、其它视为 `int/float/text` 文本框。
- 节点卡片：`headHeight = 46`、`bodyPadding = 8`，`contentHeight` 由内容高度推导；宽度约束 `min_width = 280`（后处理/预处理）。
- 分类结果经**非端口显示通道** `displayData` 传入：`{top1, top1Score, topk: [{id, score}…]}`，行数由 `Top-K` 参数决定。
- 任务参数数量不等：`yolo_detect` 5 个（含 1 个 bool）、`yolo_segment` 4 个（无 bool）、`classify` 1 个、`standard`/`yolo_letterbox`（预处理）含 `select`/`floats`/`size2`。

## 3. 参数区布局（A2）

### 3.1 行结构

- **第一行为「任务行」**：
  - 左侧：任务选择器。宽度贴合当前任务名文本（文本宽 + 图标/内边距），并**限制在 [80, 132]px**；超出则省略号。不再占满整行。
  - 右侧：
    - 若当前任务存在 `kind == bool` 的参数，显示**最早出现的那个**（灰标签 + 开关，右对齐）；
    - 否则显示**第一个参数**，宽度撑满任务行剩余空间。
  - 任务行与后续网格之间不额外加分隔线（视觉稿中的细线仅为对齐示意，实际可不画）。
- **其余参数**按 `paramDescs()` 顺序进入**两列网格**：顺序上相邻的两个「非跨列」参数拼成一行；跨列参数独占一行，且**不重排参数顺序**（其结果可能让某行右半列留空，这是有意为之）。
- 参数显隐（`showIf*`）与参数值解析规则完全沿用现状。

### 3.2 网格与尺寸

- 列数：固定 2 列；列距 10px，行距 4px。
- 控件：高 20px、圆角 5px、字号 10–11px；开关 30×17px（滑块 13px）。
- 参数控件宽度由网格列宽决定（不再由 `ParamField` 各自计算 `labelWidth/controlWidth`）。
- 单列可用宽度：`288 - 2×8(bodyPadding) = 272`，两列减去列距 10 → **每列约 131px**。
- 跨列规则：若某参数的**固有宽度**大于单列可用宽度则**跨两列**，否则占单列。固有宽度按 `kind` 估算：
  - `floats`：`labelW + n×40 + (n-1)×4`（`labelW` = 标签文本宽，“均值”≈21）→ 3 格 ≈149 → **跨列**；
  - `size2`：`labelW + 44 + 14 + 44`（标签“宽x高”≈36）→ ≈138 → **跨列**；
  - `select`：`标签文本宽 + 最长选项文本宽 + 26`（**用最长选项而非当前值**，保证切换选项时布局不抖动，也避免「处理方式 / 逐通道 Min-Max」被省略号截断）；
  - `int / float / text`：恒为单列（值是短数字）。
- 外框沿用 `NodeCard` 的 `bodyPadding = 8`，不再叠加额外边距。

### 3.3 参数控件样式

- **标签内联**：标量参数（`int/float/text/select`）的标签移到控件内部左侧（小号灰字），值在右侧；`select` 仍是「标签 + 值 + ▾」的内联框。
- `bool`：`标签 + 开关`，不画外框。
- `floats` / `size2`：标签作为行首的小号灰字；后接各自的输入格（`floats` 每格 40px、`size2` 每格 44px，均窄于现状的 54px）。
- 交互不变：单击/回车提交、焦点蓝边、菜单仍渲染到 `Overlay` 以避免被节点遮挡、提交后走 `NodeManager.commitNodeParams`。

## 4. Top-K 结果面板（T1）

- 去掉原有「Top-K　类别 id: N」标题行。
- 顶部保留一行 9px 小标题：左侧「类别」，右侧「置信度」。
- 每条结果一行，**行高 12px、无行距**：
  - 类别：`类 3`（**固定 46px**，灰字，超长省略；46px 可完整容纳 4 位 id，如 `类 2959`）；
  - 条形：高 6px、圆角 3px，轨道用背景色、填充用主题蓝，占据中间剩余宽度，比例 = 分数（钳制 0–1）；
  - 分数：固定 34px，右对齐，保留 3 位小数（沿用现有取整方式）。
- 行数 = `topkList.length`；无数据时不显示面板；行高由单一常量 `topkRowHeight = 12` 驱动（外层高度、标题行高与上边距共用）。

## 5. 影响面

- 修改：`qml/node/TaskNodeControls.qml`（布局重写）、`qml/node/ParamField.qml`（内联标签 + 由父级给宽度）、`qml/node/PostProcessNode.qml`（Top-K 面板）。
- 视觉稿中的尺寸与主题色取自 `Theme`（暗色 `#2d333b/#adbac7/#539bf5` 等）；明暗主题下均使用主题变量，不写死颜色。
- 不改：C++ 侧任务/参数定义、执行器、显示通道数据格式、`min_width`、`NodeCard`。
- 兼容性：`ParamField` 是内部控件（仅被 `TaskNodeControls` 使用），其属性变化不影响其它节点；`ParamDesc.group` 在新布局下不再用于「同一行分组」（改由「跨列」决定），但字段保留不删。

## 6. 测试步骤

1. 构建：`cmake --build build -j4`；QML 静态检查：`/usr/lib/qt6/bin/qmllint qml/node/TaskNodeControls.qml qml/node/ParamField.qml qml/node/PostProcessNode.qml qml/node/PreProcessNode.qml`。
2. 启动 `./bin/main`，逐一添加并检查五个任务的布局与交互：
   - **后处理 / YOLO 检测**：任务行 = 任务下拉 + 画分数开关；网格 = 置信/IoU、框数/线宽（2×2）。
   - **后处理 / YOLO 分割**：无 bool → 任务行右侧为置信度；其余进入网格。
   - **后处理 / 分类**：任务行右侧为 Top-K；Top-K 面板为细行列表，且行数随 `Top-K` 参数变化（如 3 / 5 / 8）。
   - **预处理 / 标准预处理**：`select`（处理方式）与 `floats`（均值/标准差）显隐联动正确；`floats` 在两列网格中按需跨列；`size2` 在「指定尺寸」下可编辑并生效。
   - **预处理 / YOLO 预处理**：`size2` 与「精度」下拉正常。
3. 交互回归：点击任务下拉切换任务（端口重建 + 参数区即时刷新）、编辑标量参数回车提交、布尔开关立即生效、`showIf` 条件参数随值显隐、节点高度自适应增长/收缩（含 `Settings.autoHeight` 关/开）。
4. 缩放与主题：`Ctrl+=` / `Ctrl+-` 到 0.8x 与 1.25x 观察文本清晰与对齐；切换明/暗主题确认无写死颜色。
5. 极窄/极宽：节点宽度拖到 `min_width=280`（不应出现控件重叠或文字截断到不可读）与 520px（网格列宽上限，控件不应无限拉伸到难看）。

## 7. 验收标准

- 默认 288px 宽下，`yolo_detect` 参数区为 3 行（任务行 + 2 行网格），节点整体高度明显小于改版前（视觉稿 ≈132px vs 现状 ≈226px 级别）。
- 任务选择器不再占满整行，且宽度随任务名自适应并有上限。
- 布尔参数出现在任务行右侧；无布尔参数时任务行右侧为第一个参数。
- 分类 Top-K 为细行列表，无冗余标题行，行数随 `Top-K` 变化。
- 预处理与后处理节点风格一致；参数显隐/提交/端口重建等行为无回归。
- `qmllint` 通过；上述人工测试全部通过。
